# Lecture 10：模型评估 (Evaluation, Model Selection and Performance Metrics)

## 1. 为什么 Evaluation 很重要

### 1.1 Machine Learning 的目标不是只在 training data 上表现好

到 Lecture 10 为止，我们已经学了很多 models，例如 KNN、Decision Tree、Naive Bayes、Linear Regression、Logistic Regression 和 SVM。前面几节课主要在问：model 怎么学？parameter 怎么找？decision boundary 怎么形成？

Lecture 10 开始换一个问题：

> 我怎么知道这个 model 真的好？

这里重点是：Machine Learning 的最终目标不是 memorise training data，而是 generalise 到 unseen data。也就是说，model 应该能在没有见过的新 samples 上做出合理 prediction。

如果一个 model 只是在 training data 上表现很好，但到了新 data 就很差，那它只是记住了 training examples，不是真的学到 general pattern。

所以 Evaluation 的核心是：

> 测试 model 在 unseen data 上的表现。

---

### 1.2 Generalisation

Generalisation 是这节课的核心概念。老师用 final exam 的例子解释：lecture 和 tutorial 就像 training process，final exam 是 test data。考试题不会完全等于你上课见过的题，但应该在同一个 subject coverage 内。

所以如果你只是背答案，那遇到新题就不会做；但如果你真的理解 concept，就能 generalise 到新问题。

ML model 也是一样：

> Memorisation = 只记住 training data。
> Generalisation = 从 training data 学到可以用于 unseen data 的 pattern。

Evaluation 就是用来判断 model 到底是在 memorise，还是在 generalise。

---

## 2. Train / Validation / Test Split

### 2.1 三个 dataset 的角色

Supervised learning 里面，data 通常会被分成：

* training data
* validation data
* test data

Training data 用来 train model，也就是让 model 学 parameters。例如 Linear Regression 学 (\beta)，Logistic Regression 学 (\theta)，Decision Tree 学 split rules。

Validation data 用来做 model selection 或 hyperparameter tuning。它不直接更新 model parameters，而是帮助我们比较不同 model settings。

Test data 是最后才使用的数据，用来评估 final model 的真实 performance。它应该保持 untouched，不参与 model selection。

所以我可以这样记：

> Training set：学 parameters。
> Validation set：选 model / tune hyperparameters。
> Test set：最终评估 generalisation。

---

### 2.2 为什么不能只用 training data evaluation

如果我们在 training data 上 evaluate model，得到的结果通常会太乐观。因为 model 已经见过这些 examples，它可能只是记住了它们。

例如一个很深的 Decision Tree 可以把 training data 几乎分得很完美，但这不代表它在 test data 上也好。

所以 evaluation 必须用 unseen data。

---

### 2.3 Test set 不能拿来 tuning

一个很常见的错误是：反复用 test set 调 hyperparameter。例如不断试 Decision Tree 的 max_depth，然后看 test accuracy，最后选 test accuracy 最高的 depth。

这样的问题是：

> test set 已经被间接用于 model selection。

这叫 data leakage。最后的 test performance 就不再是 clean estimate，因为 model 已经通过 tuning “看过” test set。

所以正确流程是：

1. 用 training data train models
2. 用 validation data 选择 best model / hyperparameter
3. 最后只用一次 test data 做 final evaluation

---

## 3. Evaluation Strategies

### 3.1 Holdout

Holdout 是最简单的 evaluation method。它把 data split 成 training set 和 test set，例如：

* 80% training / 20% test
* 70% training / 30% test
* 90% training / 10% test

流程是：

1. Randomly split dataset
2. Train model on training set
3. Evaluate model on test set

Holdout 的优点是 simple and fast。它只需要 train 一次 model，所以 computational cost 很低。

但缺点是：结果很依赖 split。如果 dataset 很小，或者 class distribution 不均衡，random split 可能会造成 training set 和 test set distribution 不一致。

---

### 3.2 Holdout 的问题

Holdout 最大问题是：

> split 方式会影响 evaluation result。

例如有三个 classes：yellow、purple、orange。如果 random split 后，test set 里面只有 yellow，没有 purple 和 orange，那么 test performance 就不能代表 model 对所有 classes 的能力。

另一种更糟的情况是：某个 class 只出现在 test set，却没有出现在 training set。那 model 根本没有机会学这个 class，但 evaluation 又要求它预测这个 class。这就造成 train-test mismatch。

所以 random split 后，最好检查：

* training set class distribution
* test set class distribution
* minority class 是否出现在两个 split 里面
* train/test 是否来自同一个 distribution

这里重点是：

> Evaluation 不只是 split data，还要看 split 后的数据是否 representative。

---

### 3.3 Stratification

Stratification 是为了解决 class imbalance split 的问题。它会尽量保持 training set 和 test set 里的 class proportion 跟原始 dataset 一致。

例如原始 data 里：

* positive = 10%
* negative = 90%

Stratified split 会尽量让 training set 和 test set 里面也保持类似比例。

这可以避免 minority class 刚好全部被分到某一个 split 里面。

所以我可以这样记：

> Stratification = 保持 label distribution 的 split。

Stratification 也可以扩展到 features，例如按 gender、profession 或 age group 做 stratified split。但如果要同时满足很多 features 的 distribution，split 会变得更复杂。

---

### 3.4 K-fold Cross-validation

K-fold Cross-validation 是更充分利用 data 的方法，特别适合 dataset 不大的情况。

流程是：

1. 把 data 分成 (K) 个 folds
2. 每次拿 (K-1) 个 folds training，剩下 1 个 fold validation
3. 重复 (K) 次
4. 把 (K) 次 scores 取 average

例如 10-fold cross-validation：

* 第 1 次：fold 1 做 validation，其余做 training
* 第 2 次：fold 2 做 validation，其余做 training
* ...
* 第 10 次：fold 10 做 validation，其余做 training

最后 average 10 次结果。

所以 Cross-validation 的核心是：

> 每个 data point 都有机会被用来 validation，也有机会被用来 training。

---

### 3.5 Cross-validation 的优缺点

Cross-validation 的优点是 data usage 更 efficient。尤其当 dataset 很小时，它比单次 holdout 更稳定。

缺点是 computationally expensive。因为 model 要 train (K) 次。如果 model 很慢，或者 hyperparameter combinations 很多，cost 会很高。

常见的 (K) 值包括：

* 5-fold
* 10-fold
* 20-fold

如果 (K=N)，也就是每次只留一个 sample 做 validation，这叫：

> Leave-One-Out Cross-Validation

它最大化使用 training data，但非常 expensive。

---

### 3.6 Temporal data 要小心 random K-fold

如果 data 有时间顺序，random K-fold 可能不合适。例如 stock market prediction，如果你用 future data 训练，再用 past data 测试，就不符合真实使用场景。

真实 stock prediction 是：

> 用过去预测未来。

所以 temporal data 通常应该用 time-based split，而不是普通 random split。

这点很重要，因为 evaluation setup 必须模拟真实 deployment situation。否则 evaluation performance 会 misleading。

---

## 4. Hyperparameter Tuning

### 4.1 Hyperparameter 是什么

Hyperparameter 是 model training 前由我们设定的值，不是 model 从 data 中直接学出来的 parameter。

例如：

KNN:

$$
K
$$

Decision Tree:

$$
max_depth
$$

Gradient Descent:

$$
learning\ rate
$$

SVM:

$$
C
$$

这些值会影响 model complexity 和 performance，所以需要 tuning。

---

### 4.2 Validation set 的作用

Validation set 用来比较不同 hyperparameter settings。

例如 Decision Tree 的 depth：

* max_depth = 1
* max_depth = 3
* max_depth = 10

如果 depth 太小，tree 太简单，容易 underfit。
如果 depth 太大，tree 太复杂，容易 overfit。
Validation set 帮我们找到一个比较合适的 depth。

所以 hyperparameter tuning 的目标是：

> 选择在 validation data 上表现最好的 setting。

---

### 4.3 Cross-validation for Hyperparameter Tuning

如果不想单独划一个 validation set，也可以在 training data 内部做 cross-validation。

流程是：

1. 保留一个 clean test set，完全不碰
2. 在 training data 内部做 k-fold cross-validation
3. 对每组 hyperparameter 计算平均 validation score
4. 选择 best hyperparameter
5. 用 selected hyperparameter 在 full training data 上重新 train model
6. 最后在 test set 上 evaluate

重点是：

> Cross-validation 可以用于 hyperparameter tuning，但 test set 仍然必须 untouched。

---

## 5. Classification Metrics

### 5.1 Accuracy

Accuracy 是最基本的 classification metric。它表示 model 预测正确的比例。

公式是：

$$
Accuracy=
\frac{TP+TN}{TP+TN+FP+FN}
$$

它很直观：

> 在所有 predictions 里面，有多少是 correct。

如果 100 个 samples 里面预测对 90 个，那么：

$$
Accuracy=90%
$$

但 accuracy 只给一个 overall number，不告诉我们 model 对每个 class 的表现，也不告诉我们是哪种 error。

---

### 5.2 Accuracy 的问题

Accuracy 在 balanced data 里通常是 good starting point。但如果 data imbalanced，accuracy 很容易 misleading。

例如一个 disease dataset，只有 1% 的人真的有病。如果 model 永远预测 “no disease”，那么它有 99% accuracy。

但这个 model 完全没有识别出真正有病的人。

Confusion matrix 可能是：

$$
TP=0,\quad FN=1,\quad FP=0,\quad TN=99
$$

Accuracy 是：

$$
Accuracy=\frac{99}{100}=99%
$$

但这个 model 对 positive class 完全没用。

所以我需要记住：

> Imbalanced data 不能只看 accuracy。

这也是为什么我们需要 precision、recall 和 F1。

---

## 6. Confusion Matrix

### 6.1 四种结果

Binary classification 里面，actual label 可以是 positive / negative，predicted label 也可以是 positive / negative。

所以有四种结果：

True Positive:

$$
TP
$$

Actual positive，predicted positive。

False Negative:

$$
FN
$$

Actual positive，predicted negative。

False Positive:

$$
FP
$$

Actual negative，predicted positive。

True Negative:

$$
TN
$$

Actual negative，predicted negative。

可以用表理解：

| Actual / Predicted | Positive | Negative |
| ------------------ | -------: | -------: |
| Positive           |       TP |       FN |
| Negative           |       FP |       TN |

---

### 6.2 Error types 不一定一样严重

False Positive 和 False Negative 的严重程度取决于 task。

Medical diagnosis 里，如果病人真的有严重疾病，但 model 预测 no disease，这是 False Negative。这个 error 可能很严重，因为病人会错过治疗。

Criminal prediction 里，如果一个无辜的人被预测为 criminal，这是 False Positive。这个 error 也很严重，因为会伤害无辜的人。

所以不同 task 应该选择不同 metric。

这里重点是：

> Not all errors are equal.

---

## 7. Precision、Recall 和 F1

### 7.1 Recall

Recall 问的是：

> 在所有 actual positive 里面，model 找回了多少？

公式是：

$$
Recall=
\frac{TP}{TP+FN}
$$

如果 recall 高，说明 false negative 少。

所以 recall 适合关注：

> 不要漏掉 positive cases。

例如 disease screening 通常很重视 recall，因为我们不想漏掉真的有病的人。

---

### 7.2 Precision

Precision 问的是：

> 在所有 predicted positive 里面，有多少是真的 positive？

公式是：

$$
Precision=
\frac{TP}{TP+FP}
$$

如果 precision 高，说明 false positive 少。

所以 precision 适合关注：

> 不要乱报 positive。

例如 spam filter 如果 precision 太低，会把很多正常 email 放进 spam folder，用户会错过重要邮件。

---

### 7.3 Precision 和 Recall 的 trade-off

Precision 和 Recall 经常有 trade-off。

如果 model 非常 aggressive，把很多 cases 都预测成 positive，那么它可能找到更多 actual positives，所以 recall 高。但同时也会把很多 negative 错报成 positive，所以 precision 低。

如果 model 非常 conservative，只在非常确定时才预测 positive，那么 precision 可能高，但 recall 可能低，因为它漏掉很多 actual positives。

所以我可以这样记：

> Recall 管漏掉多少。
> Precision 管报出来的 positive 有多准。

---

### 7.4 F1-score

F1-score 是 precision 和 recall 的 harmonic mean。

公式是：

$$
F1=
\frac{2 \times Precision \times Recall}
{Precision + Recall}
$$

F1 适合在 precision 和 recall 都重要时使用。

如果其中一个很低，F1 也会低。所以 F1 不会让一个 model 只靠很高 precision 或很高 recall 掩盖另一个很差的问题。

所以：

> F1 = precision 和 recall 的平衡指标。

---

## 8. Multi-class Evaluation

### 8.1 Multi-class Confusion Matrix

Binary confusion matrix 是 2 × 2。Multi-class confusion matrix 是 (C \times C)，其中 (C) 是 class 数量。

Rows 通常表示 actual class，columns 表示 predicted class。Diagonal 上的 values 是正确预测，off-diagonal values 是错误预测。

例如 class A 被预测成 B，就会出现在 row A、column B 的位置。

所以 multi-class confusion matrix 可以告诉我们：

> 哪些 classes 容易被混淆。


---

### 8.2 Macro Averaging

Macro averaging 是先分别计算每个 class 的 metric，然后简单取平均。

例如：

$$
MacroPrecision=
\frac{1}{C}
\sum_{c=1}^{C}Precision_c
$$

Macro averaging 给每个 class 相同权重，不管这个 class 有多少 samples。

所以：

> Macro average 适合每个 class 都同样重要的情况。

如果 minority class 很重要，macro average 比 accuracy 更有参考价值。

---
### 8.3 Micro Averaging

Micro averaging 是先把所有 classes 的 TP、FP、FN 加起来，再统一计算 metric。

例如：

$$
MicroPrecision =
\frac{\sum_c TP_c}
{\sum_c TP_c+\sum_c FP_c}
$$

$$
MicroRecall =
\frac{\sum_c TP_c}
{\sum_c TP_c+\sum_c FN_c}
$$

在 **single-label multi-class classification** 里，每个 instance 只有一个 true label，也只会被预测成一个 class。因此每一个错误预测都会同时贡献一个 FP 和一个 FN。

所以：

$$
\sum_c FP_c = \sum_c FN_c
$$

并且：

$$
MicroPrecision = MicroRecall = MicroF1 = Accuracy
$$

也就是说，在普通的 multi-class confusion matrix 里：

$$
MicroF1 =
\frac{\text{number of correct predictions}}
{\text{total number of instances}}
=
Accuracy
$$

Micro average 会受到 majority class 影响更大，因为 sample 多的 class 对总数贡献更大。

所以：

> Micro average 更反映 overall instance-level performance。
> 在 single-label multi-class classification 里，micro precision、micro recall、micro F1 和 accuracy 是相同的。


---

### 8.4 Weighted Averaging

Weighted averaging 会根据每个 class 的 support，也就是 sample 数量，给 per-class metric 加权。

公式是：

$$
WeightedMetric=
\sum_{c=1}^{C}
\frac{N_c}{N}
Metric_c
$$

其中：

$$
N_c
$$

是 class (c) 的 sample 数量。

Weighted average 介于 macro 和 micro 之间。它仍然看 per-class metrics，但 majority class 的权重更大。

所以我可以这样记：

> Macro：每个 class 一样重要。
> Micro：每个 instance 一样重要。
> Weighted：class 按 sample size 加权。

---

## 9. Regression Metrics

### 9.1 Regression evaluation 的核心

Regression 的 output 是 continuous value，所以不能直接用 correct / incorrect 来评估。

我们通常看：

$$
Error_i=y_i-\hat{y}_i
$$

其中：

$$
y_i
$$

是真实值。

$$
\hat{y}_i
$$

是预测值。

Regression metrics 基本都建立在这个 error 上。

---

### 9.2 SSE

SSE 是 Sum of Squared Errors。

公式是：

$$
SSE=
\sum_{i=1}^{N}
(y_i-\hat{y}_i)^2
$$

它把所有 squared errors 加起来。

缺点是：SSE 会随着 sample size 变大而变大，所以不同 dataset size 之间不太好比较。

---

### 9.3 MSE

MSE 是 Mean Squared Error。

公式是：

$$
MSE=
\frac{1}{N}
\sum_{i=1}^{N}
(y_i-\hat{y}_i)^2
$$

它是 SSE 除以 sample size：

$$
MSE=\frac{SSE}{N}
$$

MSE 会 penalise large errors，因为 error 被平方了。因此 MSE 对 outliers 比较 sensitive。

---

### 9.4 RMSE

RMSE 是 Root Mean Squared Error。

公式是：

$$
RMSE=
\sqrt{
\frac{1}{N}
\sum_{i=1}^{N}
(y_i-\hat{y}_i)^2
}
$$

也就是：

$$
RMSE=\sqrt{MSE}
$$

RMSE 的好处是它和 target variable 使用同一个 unit。例如预测 house price，RMSE 也是 dollars，所以更容易解释。

---

### 9.5 MAE

MAE 是 Mean Absolute Error。

公式是：

$$
MAE=
\frac{1}{N}
\sum_{i=1}^{N}
|y_i-\hat{y}_i|
$$

MAE 不会 square error，所以它不像 MSE 那样严重放大 large error。它对 outliers 没那么敏感。

所以：

> MSE / RMSE 更重视 large errors。
> MAE 对所有 errors 比较平均处理。

---

## 10. 怎么选择 Evaluation Metric

### 10.1 Classification

如果 data balanced，而且每种 error 代价差不多，可以先看 accuracy。

如果 positive class 很重要，尤其怕漏掉 positive，就看 recall。

如果 false positive 代价高，就看 precision。

如果 precision 和 recall 都重要，就看 F1。

如果是 imbalanced multi-class problem，要看 macro / weighted metrics，而不是只看 accuracy。

---

### 10.2 Regression

如果你想强烈惩罚 large errors，用 MSE 或 RMSE。

如果你想 metric 更容易解释，并且 unit 跟 target 一样，用 RMSE。

如果你不想让 outlier 影响太大，用 MAE。

所以 metric 选择要看 task：

> Evaluation metric 应该反映真实问题里什么 error 更重要。

---

## Lecture 10 总结

Lecture 10 的核心是：

> Machine Learning 不只是 train model，还必须正确 evaluate model。Evaluation 的目标是估计 model 在 unseen data 上的 generalisation ability。

我需要重点记住：

ML 的目标不是 memorisation，而是 generalisation。
Training data 用来学 parameters。
Validation data 用来 tune hyperparameters / select model。
Test data 用来 final evaluation。
Test data 不能用于 hyperparameter tuning，否则会 data leakage。
Holdout 简单快速，但受 split 影响。
Stratification 保持 class distribution。
K-fold cross-validation 更充分利用 data，但更 expensive。
Temporal data 不能随便 random split，例如 stock prediction 要用过去预测未来。
Accuracy 是最基础 metric，但 imbalanced data 下可能 misleading。
Confusion matrix 能看 TP、FP、FN、TN。
False Positive 和 False Negative 的严重程度取决于 task。
Recall 衡量 actual positive 中找回多少：

$$
Recall=\frac{TP}{TP+FN}
$$

Precision 衡量 predicted positive 中有多少是真的：

$$
Precision=\frac{TP}{TP+FP}
$$

F1 平衡 precision 和 recall：

$$
F1=
\frac{2PR}{P+R}
$$

Multi-class 可以用 macro、micro、weighted averaging。
Regression metrics 主要看 (y_i-\hat{y}_i)。
SSE 是 squared errors 总和。
MSE 是 average squared error。
RMSE 是 MSE 的平方根，unit 和 target 一样。
MAE 是 average absolute error，对 outliers 没那么敏感。

一句话总结：

> Lecture 10 讲的是如何判断 model 是否真的有用：先用正确的数据切分避免 leakage，再用合适的 metric 衡量它在 unseen data 上的表现。
