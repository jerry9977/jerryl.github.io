# Lecture 6：Naive Bayes

## 1. 从 Decision Tree 到 Naive Bayes

### 1.1 这节课在学什么

前面我们学了 KNN 和 Decision Tree。KNN 是通过 distance 找 neighbours；Decision Tree 是通过 feature split 建立 rules。Lecture 6 开始讲另一个 supervised classification model：Naive Bayes。

Naive Bayes 的核心不是 distance，也不是 tree rules，而是 probability。它会问：

> given this instance 的 features，哪个 class 最可能？

也就是：

$$
\hat{y}=\arg\max_y P(y|x)
$$

这里 (\hat{y}) 是最终预测的 label，(x) 是 test instance，(y) 是可能的 class label。

---

### 1.2 Naive Bayes 的思考方式

Naive Bayes 最重要的地方是：它会换一个角度看问题。

我们真正想知道的是：

$$
P(y|x)
$$

也就是：

> given features，class 是什么的 probability。

但这个 probability 很难直接从 training data 估计，因为 test instance 的完整 feature combination 可能从来没出现过。

所以 Naive Bayes 用 Bayes Rule 把问题反过来：

$$
P(y|x)=\frac{P(y)P(x|y)}{P(x)}
$$

它把 “given features 求 class” 转换成 “given class 看 features 有多可能”。这个角度很重要，因为在 training data 里，我们可以比较容易地数：

* 每个 class 出现多少次
* 在某个 class 下面，每个 feature value 出现多少次

所以我可以这样记：

> Naive Bayes 是用 Bayes Rule 把难算的 (P(y|x)) 转成比较容易估计的 (P(y)) 和 (P(x|y))。

---

## 2. Notation：先统一符号

### 2.1 Label 和 observation

Lecture 6 一开始先定义 notation。

(y) 表示 label，也就是我们想预测的 target class。例如：

* spam / not spam
* play / not play
* flu / cold

(x) 表示 observation，也就是一个 instance。例如一封 email、一天的 weather condition、一个病人的 symptoms。

每个 (x) 里面有多个 features：

$$
x = (x_1,x_2,\dots,x_M)
$$

其中 (x_m) 表示第 (m) 个 feature。

例如 weather dataset 里：

$$
x = (Outlook, Temperature, Humidity, Windy)
$$

---

### 2.2 Training pair

一个 labelled training example 可以写成：

$$
(x_i,y_i)
$$

这里 (i) 表示第 (i) 个 instance。整个 training set 就是一堆这样的 pairs：

$$
D_{train}={(x_1,y_1),(x_2,y_2),\dots,(x_N,y_N)}
$$

Naive Bayes 是 supervised learning，所以它需要 labelled data。Training 的目标不是学 tree，也不是学 distance，而是从这些 labelled examples 里面估计 probability parameters。

---

## 3. 为什么不能直接数完整 feature combination

### 3.1 最直接的方法为什么不现实

最直接的方法是：如果 test instance 是：

$$
x=(sunny,cool,normal,false)
$$

那我们就去 training data 里找完全一样的 row，然后看它们的 labels 是什么。如果这个 exact combination 在 training data 里出现很多次，而且大部分 label 是 yes，那就预测 yes。

这个方法在小 dataset 里看起来可行，但现实中很快会失败。因为 feature 一多，possible combinations 会爆炸。

例如有 (M) 个 attributes，每个 attribute 有 (k) 个 possible values，那么 possible feature combinations 大约是：

$$
k^M
$$

如果还有 (|Y|) 个 classes，那么要充分观察所有 combinations，需要的 data 规模大约是：

$$
O(|Y|\cdot k^M)
$$

这就是为什么老师说：如果有 20 个 binary attributes，就可能需要非常大量的数据；如果有 60 个 ternary attributes，组合数量会非常夸张。

---

### 3.2 Generalisation 的问题

如果 test instance 的完整 combination 从没在 training data 里出现过，直接 lookup 就没办法预测。但现实中的 test data 很常见就是这样：它和 training data 有一些 feature value 相似，但整个 row 不一定完全相同。

所以我们需要一个能 generalise 的 model。Naive Bayes 的做法是：

> 不要求完整 feature combination 出现过，只要求每个 feature value 在某些 class 下出现过。

这就是它为什么可以在小数据或高维数据里还可以工作。

---

## 4. Bayes Rule 到 Naive Bayes Formula

### 4.1 Bayes Rule

目标是：

$$
\hat{y}=\arg\max_y P(y|x)
$$

根据 Bayes Rule：

$$
P(y|x)=\frac{P(y)P(x|y)}{P(x)}
$$

因为我们是在同一个 test instance (x) 上比较不同的 (y)，所以 denominator (P(x)) 对所有 classes 都一样。它不会影响哪个 class 最大。因此 prediction 时可以忽略：

$$
\hat{y}=\arg\max_y P(y)P(x|y)
$$

这里很重要：我们不是说 (P(x)) 不存在，而是说它对 class ranking 没有影响。

所以 Naive Bayes prediction 用的是 unnormalised score：

$$
score(y)=P(y)P(x|y)
$$

最后选 score 最大的 class。

---

### 4.2 X 其实是很多 features

问题是 (x) 不是一个 single value，它是一组 features：

$$
x=(x_1,x_2,\dots,x_M)
$$

所以：

$$
P(x|y)=P(x_1,x_2,\dots,x_M|y)
$$

这个 joint conditional probability 还是很难估计，因为它仍然要求我们见过完整 feature combination。

这时候 “naive” assumption 就出现了。

---

### 4.3 Naive Assumption

Naive Bayes 假设：

> given class (y)，所有 features 彼此 independent。

也就是说：

$$
P(x_1,x_2,\dots,x_M|y)
\approx
\prod_{m=1}^{M}P(x_m|y)
$$

所以完整公式变成：

$$
\hat{y}
=

\arg\max_y P(y)\prod_{m=1}^{M}P(x_m|y)
$$

这就是 Naive Bayes classifier 的核心公式。

---

### 4.4 为什么说它 “Naive”

这个 assumption 通常是不真实的。例如 email spam classification 里，如果一封 email 已经包含 “free”，它也可能更容易包含 “money” 或 “click”。Words 之间显然不是完全 independent。

但 Naive Bayes 仍然经常表现不错。原因是：classification 不一定需要得到真实的 probability distribution，我们只需要能把最可能的 class 排在前面。

所以我可以这样记：

> Naive Bayes 的 assumption 很强，甚至经常是错的；但只要 class ranking 对，它就仍然有用。

---

## 5. Naive Bayes 的 Assumptions

### 5.1 Feature conditional independence

最核心的 assumption 是：

$$
P(x_1,x_2,\dots,x_M|y)
\approx
\prod_{m=1}^{M}P(x_m|y)
$$

意思是：

> 在 class 已知的情况下，每个 feature 和其他 features independent。

这让 model 不需要估计完整 feature combination，只需要估计每个 feature 在每个 class 下的 probability。

---

### 5.2 Instances independent

Naive Bayes 也假设 training instances 之间是 independent 的。也就是说，每一行 data 都是独立抽样来的。

这也是很多 ML model 的常见假设。现实中不一定完全成立，但作为建模简化很常见。

---

### 5.3 Training 和 Test distribution 一致

另一个重要 assumption 是：

> training data 和 test data 来自相同 distribution。

如果 training data 里 flu 占 90%，cold 占 10%，但真实 test environment 里是 50/50，那么 model 学到的 prior 就会偏。这种 distribution mismatch 会让 model generalise 得不好。

所以这里可以连接前面课程的 generalisation：

> model 学到的是 training data 的 pattern；如果 training data 不代表真实 test data，prediction 就会有问题。

---

## 6. Training Naive Bayes：到底在学什么

### 6.1 Training = 估计 prior 和 likelihood

Naive Bayes 的 training 不像 Decision Tree 那样 build tree，也不像后面 regression 那样做 optimization。它主要是在 training data 里面数 probability。

Training 要学两类东西：

第一是 prior：

$$
P(y)
$$

也就是每个 class 本身出现的 probability。

第二是 likelihood：

$$
P(x_m|y)
$$

也就是在某个 class 下，某个 feature value 出现的 probability。

所以我可以这样记：

> Naive Bayes training = count priors + count likelihoods。

---

### 6.2 Prior Example

假设 diagnosis dataset 里面有 5 rows：

* Flu = 3
* Cold = 2

那么：

$$
P(Flu)=\frac{3}{5}
$$

$$
P(Cold)=\frac{2}{5}
$$

这就是 prior probability。它表示在没有看到 symptoms 之前，单看 training data，哪个 class 更常见。

---

### 6.3 Likelihood Example

现在看 likelihood。例如在 Flu 的 3 个 examples 里，Headache = severe 出现了 3 次，那么：

$$
P(Headache=severe|Flu)=\frac{3}{3}=1
$$

如果 Headache = mild 在 Flu 里面出现 0 次：

$$
P(Headache=mild|Flu)=\frac{0}{3}=0
$$

如果 Cough = mild 在 Flu 里面出现 2 次：

$$
P(Cough=mild|Flu)=\frac{2}{3}
$$

这些 likelihoods 就是 Naive Bayes prediction 时要查的表。

---

## 7. Prediction：怎么用 Naive Bayes 分类

### 7.1 对每个 class 算 score

假设新病人的 symptoms 是：

* Headache = mild
* Cough = mild
* Temperature = normal
* Sore = yes

我们要比较：

$$
score(Cold)
$$

和：

$$
score(Flu)
$$

对于 Cold：

$$
score(Cold)
=

P(Cold)
P(Headache=mild|Cold)
P(Cough=mild|Cold)
P(Temperature=normal|Cold)
P(Sore=yes|Cold)
$$

对于 Flu：

$$
score(Flu)
=

P(Flu)
P(Headache=mild|Flu)
P(Cough=mild|Flu)
P(Temperature=normal|Flu)
P(Sore=yes|Flu)
$$

最后选择 score 较大的 class。

---

### 7.2 Score 不是完整 probability

这里有一个很容易错的地方。因为我们 prediction 时忽略了 denominator (P(x))，所以算出来的 score 通常不会加起来等于 1。

也就是说，如果：

$$
score(Cold)=0.025
$$

不能直接说：

> Cold 的 probability 是 2.5%。

它只是一个 unnormalised score，用来和其他 classes 比较。

所以我需要记住：

> Naive Bayes prediction 主要看 relative ranking，不一定直接得到 normalised probability。

如果要得到真正的 posterior probability，还需要除以所有 class scores 的总和。

---

## 8. Zero Probability Problem

### 8.1 为什么一个 0 会毁掉整个 prediction

Naive Bayes 会把很多 likelihoods 乘起来：

$$
P(y)\prod_{m=1}^{M}P(x_m|y)
$$

如果其中任何一个 likelihood 是 0，整个 score 就会变成 0。

例如：

$$
P(Headache=mild|Flu)=0
$$

那么无论其他 symptoms 多么支持 Flu：

$$
score(Flu)=0
$$

这不太合理。因为 training data 没见过某个 combination，不代表它现实中不可能发生。尤其当 training data 很小的时候，0 很可能只是因为 sample 不够，而不是真正 impossible。

所以这里的问题是：

> unseen feature value 会让 class score 直接归零。

---

### 8.2 为什么大数据也不能完全解决

即使 training data 变大，zero probability 仍然可能出现。因为 feature combinations 很多，尤其在 text classification 里，vocabulary 很大，很多 words 可能只在某些 classes 下没出现过。

所以 smoothing 不是小 dataset 才需要，而是 Naive Bayes 里非常常见的 practical fix。

---

## 9. Smoothing

### 9.1 Epsilon Smoothing

Epsilon smoothing 的想法是：如果某个 probability 是 0，就用一个非常小的 positive number (\epsilon) 代替它。

例如：

$$
P(x_m=j|y=k)=0
$$

可以改成：

$$
P(x_m=j|y=k)=\epsilon
$$

这样整个 product 不会直接变成 0。

(\epsilon) 通常要非常小。Transcript 里老师解释，它应该小于大约：

$$
\frac{1}{N}
$$

其中 (N) 是 training instances 的数量。直觉是：如果 training set 里从来没见过它，那它的 probability 应该比 observed event 更小，但不应该是 0。

---

### 9.2 Laplace Smoothing

Laplace smoothing 更系统。它会给每个 possible feature value 加一个 pseudocount。

如果某个 feature 有 (V_m) 个 possible values，那么：

$$
P(x_m=j|y=k)
=

\frac{count(y=k,x_m=j)+\alpha}
{count(y=k)+\alpha V_m}
$$

其中：

* (\alpha) 是 pseudocount
* 常见选择是 (\alpha=1)
* (V_m) 是 feature (m) 的 possible values 数量

例如 Headache 有三个 values：

* severe
* mild
* no

如果在 Flu class 中：

$$
count(Flu,Headache=severe)=3
$$

$$
count(Flu)=3
$$

使用 (\alpha=1) 后：

$$
P(Headache=severe|Flu)
=

# \frac{3+1}{3+3}

\frac{4}{6}
$$

原本没有出现的 mild：

$$
P(Headache=mild|Flu)
=

# \frac{0+1}{3+3}

\frac{1}{6}
$$

所以 Laplace smoothing 会把原本 0 的 probability 变成一个小的非零值。

---

### 9.3 Smoothing 的 tradeoff

Smoothing 的好处是：

> reduces variance

因为 model 不会因为 training data 里某个 value 没出现，就把 probability 判成 0。它降低了 model 对单个 observation 或 non-observation 的敏感度。

但 smoothing 也有代价：

> adds bias

因为 smoothing 后的 probability 不再是纯粹从 observed data 里得到的 maximum likelihood estimate。我们人为加入了 pseudocount，也就是加入了一点 prior assumption。

所以我可以这样记：

> Smoothing 让 model 更稳定，但也让 probability 不再完全等于 data frequency。

---

## 10. 不同 Data Type 的 Naive Bayes

### 10.1 核心公式不变

Naive Bayes 的核心公式一直不变：

$$
\hat{y}
=

\arg\max_y P(y)\prod_{m=1}^{M}P(x_m|y)
$$

变化的是：

> (P(x_m|y)) 怎么计算。

如果 feature 是 categorical，就用 count-based probability。
如果 feature 是 binary，就用 Bernoulli distribution。
如果 feature 是 continuous，就用 Gaussian distribution。

---

### 10.2 Categorical Naive Bayes

Categorical Naive Bayes 适合 categorical features，例如：

* Outlook = sunny / rainy / overcast
* Temperature = hot / mild / cool
* Diagnosis = flu / cold

它的 likelihood 用 relative frequency 估计：

$$
P(x_m=j|y=k)
=

\frac{count(y=k,x_m=j)}{count(y=k)}
$$

如果加 Laplace smoothing：

$$
P(x_m=j|y=k)
=

\frac{count(y=k,x_m=j)+\alpha}
{count(y=k)+\alpha V_m}
$$

所以 Categorical NB 的训练就是数每个 class 下每个 category 出现的次数。

---

### 10.3 Bernoulli Naive Bayes

Bernoulli Naive Bayes 适合 binary feature vectors，也就是每个 feature 只有 0 或 1。

例如 text classification 里，可以把每个 word 表示成：

* 1 = word appears
* 0 = word does not appear

Bernoulli NB 关心的是某个 feature 是否出现，而不是出现多少次。

所以我可以记：

> Bernoulli NB = binary features。

---

### 10.4 Gaussian Naive Bayes

Gaussian Naive Bayes 适合 continuous numerical features，例如：

* temperature
* height
* fatigue score
* stock return

它假设在给定 class 后，每个 numerical feature follows Gaussian distribution。

也就是说：

$$
x_m|y \sim \mathcal{N}(\mu_{y,m},\sigma_{y,m})
$$

Training 时，对于每个 class (y) 和每个 feature (x_m)，估计：

$$
\mu_{y,m}
$$

和：

$$
\sigma_{y,m}
$$

Mean 是该 class 下这个 feature 的平均值：

$$
\mu_{y,m}
=

\frac{1}{count(y)}
\sum_{i:y_i=y}x_m^{(i)}
$$

Standard deviation 是该 class 下这个 feature 的分散程度：

$$
\sigma_{y,m}
=

\sqrt{
\frac{
\sum_{i:y_i=y}(x_m^{(i)}-\mu_{y,m})^2
}
{count(y)}
}
$$

Prediction 时，用 Gaussian PDF 计算 likelihood：

$$
P(x_m=j|y=k)
=

\frac{1}{\sigma_{k,m}\sqrt{2\pi}}
\exp\left(
-\frac{1}{2}
\left(
\frac{j-\mu_{k,m}}{\sigma_{k,m}}
\right)^2
\right)
$$

所以 Gaussian NB 的 training 不是数 category，而是估计每个 class-feature pair 的 mean 和 standard deviation。

---

### 10.5 Multinomial Naive Bayes

Multinomial Naive Bayes 通常用于 count data，尤其是 text classification。

例如一篇 document 里：

* word “free” 出现 3 次
* word “money” 出现 2 次
* word “click” 出现 5 次

这不是简单的 appears / not appears，而是 count。Multinomial NB 适合这种 word count representation。

所以可以简单区分：

> Bernoulli NB 看 word 是否出现。
> Multinomial NB 看 word 出现多少次。
> Categorical NB 看 feature 属于哪个 category。
> Gaussian NB 看 continuous numerical value。

---

## 11. Underflow 和 Log Transformation

### 11.1 为什么会 underflow

Naive Bayes 要把很多 probability 乘起来。每个 probability 都在 0 到 1 之间。如果 features 很多，乘积会变得非常非常小。

例如：

$$
0.01\times0.02\times0.03\times\dots
$$

最后可能小到 computer floating-point representation 无法稳定表示，这叫 underflow。

---

### 11.2 用 log 把 product 变成 sum

解决方法是做 log transformation：

原本：

$$
\hat{y}
=

\arg\max_y P(y)\prod_{m=1}^{M}P(x_m|y)
$$

取 log 后：

$$
\hat{y}
=

\arg\max_y
\left[
\log P(y)
+
\sum_{m=1}^{M}\log P(x_m|y)
\right]
$$

因为 log 是 monotonic transformation，所以不会改变哪个 class 最大。它只是把很小的乘积变成比较稳定的加法。

所以我可以这样记：

> Naive Bayes 实作时通常用 log-probability，而不是直接乘 probability。

---

## 12. Continuous Feature 的 Smoothing

### 12.1 Gaussian NB 的 zero variance problem

Categorical NB 的问题是 unseen feature value 会造成 zero probability。Gaussian NB 不太会有 unseen value 问题，因为 continuous distribution 可以对任何 value 计算 density。

但 Gaussian NB 会有另一个问题：

> 如果某个 feature 在某个 class 下所有 observed values 都一样，standard deviation 会变成 0。

如果：

$$
\sigma=0
$$

Gaussian PDF 里面会出现除以 0 的问题。

---

### 12.2 怎么处理

一种方法是 ignore 这个 feature。如果这个 feature 在所有 classes 里面都是 constant，那么它没有区分能力，删除是合理的。

另一种方法是给 variance 或 standard deviation 加一个小的 smoothing value：

$$
\sigma \rightarrow \sigma+\epsilon
$$

这样可以避免 division by zero。Sklearn 里面也会使用类似的小 smoothing value。

所以 continuous feature 也需要 smoothing，只是原因不是 unseen category，而是 zero variance。

---

## 13. Naive Bayes 的优点和缺点

### 13.1 优点

Naive Bayes 的优点是 easy to build and estimate。Training 主要就是 counting 或 estimate mean / standard deviation，所以很快。

它也很适合 high-dimensional features，例如 text classification。因为它不需要估计完整 feature combination，只需要估计每个 feature 在每个 class 下的 probability。

它也比较容易解释。我们可以看某个 prediction 是因为哪些 likelihoods 支持某个 class。

所以 Naive Bayes 经常是 classification project 的 good starting point。

---

### 13.2 缺点

最大缺点是 independence assumption 很强，现实中通常不成立。Features 往往不是 independent。

另外，如果没有 smoothing，zero probability 会让 prediction 变得很脆弱。

还有，Naive Bayes 输出的 probability 不一定 calibrated 得很好。它可能能选对 class，但 probability 数值本身不一定准确。

所以：

> Naive Bayes often works surprisingly well, but its probability assumptions are simplified and often wrong.

---

## Lecture 6 总结

Lecture 6 的核心是：

> Naive Bayes 用 Bayes Rule 和 conditional independence assumption，把 classification 变成一个可计算的 probability ranking problem。

我需要重点记住：

Naive Bayes 是 supervised probabilistic classifier。
目标是选择 (P(y|x)) 最大的 class。
Bayes Rule 把 (P(y|x)) 转成 (P(y)P(x|y))。
因为 (P(x)) 对所有 class 一样，prediction 时可以忽略。
Naive assumption 是：given class，features independent。
核心公式是：

$$
\hat{y}
=

\arg\max_y P(y)\prod_{m=1}^{M}P(x_m|y)
$$

Training 主要是在估计 priors 和 likelihoods。
Prior 是 class distribution。
Likelihood 是 feature value given class 的 probability。
Prediction 算的是 unnormalised score，不一定是完整 probability。
Zero probability problem 会让整个 class score 变成 0。
Smoothing 用来避免 unseen feature value 造成 zero probability。
Laplace smoothing 加 pseudocount，会 reduce variance 但 add bias。
Categorical NB 用于 categorical features。
Bernoulli NB 用于 binary features。
Gaussian NB 用于 continuous features。
Multinomial NB 常用于 count data，例如 word counts。
实际 implementation 常用 log transformation 避免 underflow。
Naive Bayes 简单、快、可解释、适合高维数据，但 independence assumption 很强。

一句话总结：

> Naive Bayes 的本质是：用 class prior 和 feature likelihoods 给每个 class 算一个 score，然后选择最可能的 class；它假设 features 在给定 class 后互相 independent，所以计算变得简单。
