# Lecture 5：决策树 (Decision Trees)

## 1. 从 KNN 到 Decision Tree

### 1.1 这节课为什么开始讲 Decision Tree

前面我们已经学了 KNN 和 probability。KNN 的想法是：新的 instance 来了以后，去 training data 里面找最相似的 neighbours，然后根据 neighbours 的 label 做 prediction。KNN 很直观，但它不是一个会主动总结规则的 model，它更像是把 training data 存起来，等 test instance 出现时才计算 distance。

Decision Tree 则是另一种思路。它会从 training data 里面学出一组 decision rules。也就是说，它不是每次 prediction 都重新比较所有 training examples，而是先把 data 里面的 pattern 整理成一棵 tree。Prediction 的时候，只需要沿着 tree 的 branch 一步一步走到 leaf，就能得到 label。

所以我可以这样理解：

> KNN 是用 similarity 做 prediction。
> Decision Tree 是用 rules 做 prediction。

---

### 1.2 Decision Tree 为什么直观

Decision Tree 很像人类平时做决定的方式。例如我要不要去打球，我可能会问：

* 今天下雨吗？
* 风大吗？
* 温度合适吗？
* 湿度高吗？

如果下雨很大，我可能不去；如果天气好，我可能去。Decision Tree 就是把这种判断过程形式化成一棵 tree。每一个 node 问一个 feature，每一个 branch 对应 feature value，最后 leaf 给出 prediction。

所以 Decision Tree 的核心直觉是：

> 一步一步问问题，把 data 分成越来越 pure 的 groups。

---

## 2. Baseline Models：Zero-R 和 One-R

### 2.1 为什么要先讲 baseline

Lecture 5 没有直接进入复杂 tree，而是先讲 baseline。这里我觉得很重要，因为 baseline 是 ML 里面判断 model 有没有用的起点。

如果一个复杂 model 连最简单的 baseline 都打不过，那这个 model 基本没有价值。所以 baseline 不是“没用的模型”，而是用来做 comparison 的最低标准。

---

### 2.2 Zero-R：完全不看 features

Zero-R 是最简单的 classifier。它完全不看任何 feature，只预测 training data 里面最常见的 label。

例如诊断数据里面，label 有 Flu 和 Cold。如果 10 个 instances 里面有 8 个是 Flu，那么 Zero-R 永远预测 Flu。

Training accuracy 就是：

$$
\frac{8}{10}=80%
$$

这听起来还不错，但它其实没有学任何真正的 rule。它只是利用 class imbalance，永远预测 majority class。

所以 Zero-R 的重点是：

> 不使用任何 feature，只预测 majority class。

它的作用是 baseline。如果我的 Decision Tree、KNN 或其他 model 连 Zero-R 都比不过，那说明我的 model 很可能没有学到有用 pattern。

---

### 2.3 One-R：只用一个 feature

One-R 比 Zero-R 稍微复杂一点。它会选一个最好的 feature，然后只用这个 feature 做 prediction。

例如 golf dataset 里面有这些 features：

* Outlook
* Temperature
* Humidity
* Windy

如果只用 Outlook，那么 Outlook 有三个 possible values：

* sunny
* overcast
* rainy

对于每一个 value，我们看 training data 里面 majority label 是什么。

如果 sunny 大部分是 no，那么：

> Outlook = sunny → Play = no

如果 overcast 全部是 yes，那么：

> Outlook = overcast → Play = yes

如果 rainy 大部分是 yes，那么：

> Outlook = rainy → Play = yes

这就形成了一个很浅的 tree，也叫 decision stump。

---

### 2.4 One-R 怎么选 best feature

One-R 会尝试每一个 feature，然后看哪个 feature 的 prediction error 最低，或者 accuracy 最高。

例如：

| Feature     | Error Rate |
| ----------- | ---------: |
| Outlook     |       4/14 |
| Temperature |       5/14 |
| Humidity    |       4/14 |
| Windy       |       5/14 |

这里 Outlook 和 Humidity 都是 4/14 error，所以它们都可以算是比较好的 one-feature rule。

所以 One-R 的重点是：

> 只用一个 feature，选择 training data 上犯错最少的 feature。

它比 Zero-R 更有信息，因为它至少使用了一个 attribute；但它还是很简单，所以也常用作 baseline。

---

## 3. Decision Tree 的结构

### 3.1 Tree 的组成

Decision Tree 由几个部分组成：

**Root node** 是 tree 最上面的 node，也是第一个要检查的 feature。

**Internal node** 是中间的 decision point，每个 node 也对应一个 feature。

**Branch** 是 feature value 对应的路径。

**Leaf node** 是最终 prediction 的位置。

例如：

Outlook 是 root node。
Outlook = sunny / overcast / rainy 是 branches。
如果走到某个 leaf，leaf 可能预测 yes 或 no。

---

### 3.2 Pure Node

如果一个 node 里面的 instances 全部属于同一个 label，那么这个 node 就是 pure node。

例如 Outlook = overcast 的 instances 全部都是 Play = yes，那么这个 branch 已经没有 uncertainty 了，可以直接变成 leaf：

> Outlook = overcast → yes

Pure node 很重要，因为 Decision Tree 的目标就是不断 split data，让 leaf nodes 尽量 pure。

所以我可以这样记：

> Decision Tree 的训练过程，就是不断找 feature，把 data split 成更 pure 的 subsets。

---

### 3.3 Tree 的 prediction 怎么走

如果有一个新的 test instance：

| Outlook | Temperature | Humidity | Windy |
| ------- | ----------- | -------- | ----- |
| rainy   | cool        | high     | false |

Decision Tree 会先看 root node。假设 root 是 Outlook，那么它看到 rainy，就走 rainy branch。接着如果 rainy branch 下面还有 Windy node，它会继续看 Windy = false。最后走到 leaf，得到 prediction，例如 Play = yes。

所以 prediction 过程非常可解释：

> 每一步为什么这样走，都能从 feature value 里面看出来。

这也是 Decision Tree 最大的优点之一。

---

## 4. 怎么 build 一棵 Decision Tree

### 4.1 不能暴力找 global optimal tree

理论上，我们可以尝试所有可能的 trees，然后选表现最好的那一棵。但这在现实中几乎不可行，因为 feature 一多，可能的 tree 数量会爆炸。

如果有 100 个 features，root node 就有 100 种选择。选完 root 后，下一层又有很多选择。要找 global optimal tree 会非常 expensive。

所以 Decision Tree 通常不是找 global optimal，而是用 greedy heuristic。

也就是说：

> 每一步先选当前看起来最好的 feature。

这个不保证 global optimal，但 practical，而且速度快。

---

### 4.2 Decision Tree 想要什么样的 split

一个好的 split 应该让分出来的 subsets 更 pure。也就是说，每个 subset 里面最好大部分都是同一个 class。

例如一个 split 之后：

* subset 1 几乎全是 yes
* subset 2 几乎全是 no

那这个 split 就很好。

但如果 split 后每个 subset 还是 yes/no 混在一起，那这个 feature 就没有太多帮助。

所以 Decision Tree 的核心问题是：

> Which feature gives the best split?

Lecture 5 后面用 Entropy 和 Information Gain 来回答这个问题。

---

### 4.3 Tree 不能无限长

Decision Tree 如果一直 split 下去，最后可能每个 leaf 都只剩一两个 training instances。这样 training accuracy 可能很高，但 model 很容易 overfit。

这就像把 training data 里面的 noise 也记住了。它可能在 training data 上表现很好，但在 unseen data 上表现差。

所以我们需要考虑：

* tree 应该长多深？
* 什么时候停止 splitting？
* leaf 多 pure 才够？
* tree 太复杂会不会 overfit？

这里其实已经开始接到后面的 generalisation 和 overfitting。

---

## 5. ID3 Algorithm

### 5.1 ID3 是什么

ID3 是一个经典的 Decision Tree building algorithm。它是 recursive algorithm，也就是说它会不断对 subset 继续调用自己。

ID3 的核心选择标准是：

> 每一步选择 Information Gain 最高的 feature。

它的流程大概是：

1. 从当前 dataset 开始
2. 如果当前 node 已经 pure，停止
3. 如果还不 pure，计算每个 feature 的 Information Gain
4. 选择 Information Gain 最大的 feature
5. 按照这个 feature 的 values 建立 branches
6. 对每个 branch 里面的 subset 继续重复同样过程

所以 ID3 是：

> greedy + recursive。

Greedy 是因为它每一步只选当前最好的 feature。
Recursive 是因为它会对子集继续重复建树。

---

### 5.2 ID3 的停止条件

最直接的停止条件是：

> node 已经 pure。

也就是说，当前 subset 里面全部是同一个 class，那就没必要继续 split。

但现实中不一定每次都能达到完全 pure。很多时候 data 有 noise，或者 features 不够强，所以可能永远分不干净。实际使用时可以设置 threshold，例如：

> 如果某个 node 里面 95% 都是同一个 class，就停止。

所以我可以这样记：

> 理想情况：pure leaf 就停止。
> 实际情况：够 pure 就可以停止。

---

## 6. Entropy：怎么量化 uncertainty

### 6.1 Entropy 的直觉

Entropy 是用来衡量 uncertainty 的。一个 event 如果非常确定，entropy 就低；如果很不确定，entropy 就高。

例如 double-head coin。无论怎么 flip，结果都是 head。所以没有 uncertainty：

$$
H=0
$$

Fair coin 则有 head 和 tail 两种可能，而且各自 probability 都是 0.5。我们不知道下一次会是哪一个，所以 uncertainty 比较高：

$$
H=1
$$

所以 entropy 的直觉是：

> uncertainty 越大，entropy 越高。
> 越 pure，entropy 越低。

---

### 6.2 Entropy 公式

对于一个 discrete random variable (X)，entropy 是：

$$
H(X)=-\sum_{i=1}^{n}P(i)\log_2P(i)
$$

这里：

* (P(i)) 是第 (i) 个 outcome 的 probability
* (\log_2) 表示用 bits 来度量 information
* 如果某个 probability 是 0，通常定义 (0\log_2 0 = 0)

这个公式可以理解成：

> 所有 possible outcomes 的 average surprise。

低 probability 的 event 如果发生，会带来更高 surprise；但 entropy 会用 probability 加权，所以 rare event 不会无限支配整个 measure。

---

### 6.3 Coin Example

Double-head coin：

$$
P(head)=1,\quad P(tail)=0
$$

$$
H(X)=-[1\log_2 1+0\log_2 0]=0
$$

Fair coin：

$$
P(head)=0.5,\quad P(tail)=0.5
$$

$$
H(X)=-[0.5\log_2 0.5+0.5\log_2 0.5]
$$

$$
H(X)=1
$$

所以：

> 完全确定 → entropy = 0
> 二元平均不确定 → entropy = 1

---

### 6.4 Diagnosis Example

如果 diagnosis 有 5 个 examples，其中：

* Flu = 3
* Cold = 2

那么：

$$
P(Flu)=\frac{3}{5}
$$

$$
P(Cold)=\frac{2}{5}
$$

Entropy 是：

$$
H(Diagnosis)
=

-\left[
\frac{3}{5}\log_2\frac{3}{5}
+
\frac{2}{5}\log_2\frac{2}{5}
\right]
$$

大约是：

$$
H(Diagnosis)\approx 0.97
$$

这表示 label 还有不少 uncertainty，因为 Flu 和 Cold 都存在。如果全部都是 Flu，那 entropy 就是 0，也就不需要 model 了。

---

## 7. Conditional Entropy：知道某个 feature 之后还剩多少 uncertainty

### 7.1 Conditional Entropy 的直觉

Entropy 是“不知道任何 feature 时，label 有多不确定”。Conditional entropy 则是：

> 如果我知道某个 feature value，label 还剩多少 uncertainty？

例如 diagnosis dataset 里面，如果 headache = severe 时，所有 cases 都是 Flu，那么在这个 condition 下：

$$
H(Diagnosis|Headache=severe)=0
$$

这说明 headache = severe 这个 condition 对 prediction 很有帮助，因为它让 diagnosis 变得确定。

---

### 7.2 Conditional Entropy 公式

公式是：

$$
H(X|Y)=\sum_{y\in Y}P(y)H(X|Y=y)
$$

这里可以理解成：

> 对每一个 feature value 分别算 label entropy，然后按这个 feature value 出现的比例做 weighted average。

例如 Headache 有三个 values：

* severe
* mild
* no

那么：

$$
H(Diagnosis|Headache)
=

P(severe)H(Diagnosis|severe)
+
P(mild)H(Diagnosis|mild)
+
P(no)H(Diagnosis|no)
$$

所以 Conditional Entropy 衡量的是：

> 知道某个 feature 之后，target label 平均还剩多少不确定性。

---

## 8. Information Gain：怎么选 split feature

### 8.1 Information Gain 的直觉

Information Gain 是 Decision Tree 里面最关键的概念。它衡量：

> 知道某个 feature 之后，uncertainty 减少了多少。

也就是说，一个 feature 如果能让 label 变得更确定，它的 Information Gain 就高。

公式是：

$$
IG(X,Y)=H(X)-H(X|Y)
$$

在 Decision Tree 里，通常可以理解成：

$$
IG(Label,Feature)=H(Label)-H(Label|Feature)
$$

所以：

> Information Gain = 原本 label 的 uncertainty − 知道 feature 后剩下的 uncertainty。

---

### 8.2 Golf Dataset：Outlook Example

Golf dataset 里面，target label 是 Play。Training data 里面：

* yes = 9
* no = 5

所以：

$$
H(Play)
=

-\left[
\frac{9}{14}\log_2\frac{9}{14}
+
\frac{5}{14}\log_2\frac{5}{14}
\right]
$$

$$
H(Play)\approx 0.94
$$

现在如果我们选择 Outlook 作为 split feature，它有三个 values：

* sunny
* overcast
* rainy

所以我们要算：

$$
H(Play|Outlook)
=

P(sunny)H(Play|sunny)
+
P(overcast)H(Play|overcast)
+
P(rainy)H(Play|rainy)
$$

Slides 中算出来：

$$
H(Play|Outlook)=0.693
$$

所以：

$$
IG(Play,Outlook)
=

H(Play)-H(Play|Outlook)
$$

$$
IG(Play,Outlook)=0.94-0.693=0.247
$$

这表示：

> 知道 Outlook 以后，Play 的 uncertainty 减少了 0.247。

---

### 8.3 为什么选 Information Gain 最大的 feature

ID3 会对所有 features 都算 Information Gain，例如：

* Outlook
* Temperature
* Humidity
* Windy

然后选择 Information Gain 最大的 feature 作为当前 node。

在 golf dataset 里，Outlook 的 Information Gain 最高，所以它被选为 root node。

这比 One-R 的 training accuracy 更细。因为 One-R 可能发现 Outlook 和 Humidity 的 accuracy 一样，但 Information Gain 可以进一步比较它们对 uncertainty 的 reduction。

所以我可以这样记：

> Decision Tree 选 feature，不只是看 accuracy，而是看哪个 feature 最能减少 label uncertainty。

---

## 9. ID3 建树过程：从 root 到 leaf

### 9.1 先选 root node

第一步，对所有 features 计算 Information Gain。选 Information Gain 最高的 feature 作为 root node。

在 golf dataset 里：

> root = Outlook

然后根据 Outlook 的 values 分出 branches：

* sunny
* overcast
* rainy

---

### 9.2 Pure branch 直接停止

如果某个 branch 已经 pure，就停止。

例如：

> Outlook = overcast

对应的 examples 全部是 Play = yes，所以这个 branch 直接变成 leaf：

> overcast → yes

---

### 9.3 不 pure 的 branch 继续 split

如果某个 branch 还不 pure，就只拿这个 branch 里面的 subset 继续建 tree。

例如 Outlook = sunny 的 subset 里面有 yes 和 no，所以还需要继续 split。注意，这时候不是回到完整 dataset，而是只看 sunny subset。

在这个 subset 里，已经用过 Outlook，所以接下来只考虑剩余 features：

* Temperature
* Humidity
* Windy

然后重新计算 Information Gain。Lecture 里 sunny branch 选择 Humidity，因为它能把 sunny subset 分成 pure leaves。

类似地，rainy branch 后面选择 Windy。

所以 ID3 的建树逻辑是：

> 每个 node 都在自己的 subset 上重新选择 best feature。

---

## 10. ID3 的问题：容易偏向 many-valued features

### 10.1 为什么 ID3 会有 bias

ID3 使用 Information Gain，但 Information Gain 有一个问题：

> 它偏好有很多 attribute values 的 feature。

最极端的例子是 ID column。每个 student ID 都是 unique 的。如果用 ID 来 split，每个 branch 可能只有一个 instance，那么每个 leaf 都会非常 pure。

Training data 上看起来完美，但这个 tree 完全没有 generalisation。因为新的 student ID 从来没见过，model 不知道怎么分类。

所以这里的重点是：

> pure 不一定等于 useful。

如果 split 太细，它可能只是记住 training data，而不是学到 general rule。

---

### 10.2 Gain Ratio

为了解决 Information Gain 偏向 many-valued feature 的问题，C4.5 引入 Gain Ratio。

公式是：

$$
GainRatio=\frac{Information\ Gain}{Split\ Information}
$$

Split Information 衡量的是这个 feature 本身 split 得有多碎。它类似于 feature values distribution 的 entropy：

$$
SplitInfo(Y)
=

-\sum_{v\in Values(Y)}P(v)\log_2P(v)
$$

如果一个 feature 有很多 values，而且 split 很碎，那么 Split Information 会比较高。用 Information Gain 除以 Split Information，就可以惩罚这种过度分裂。

所以我可以这样记：

> Information Gain 喜欢 pure split。
> Gain Ratio 会惩罚太碎的 split。

---

## 11. Stopping 和 Overfitting

### 11.1 为什么需要 stopping

Decision Tree 很容易 overfit。如果一直 split 到每个 leaf 都 pure，tree 可能会记住 training data 里面的 noise。

例如某个特殊 combination 在 training data 里刚好对应 yes，但这可能只是偶然。Tree 如果为了这个偶然现象建立一个 branch，就会让 model 变得太复杂。

所以 Decision Tree 需要 stopping criteria。

---

### 11.2 常见 stopping idea

可以在这些情况下停止：

* node 已经 pure
* node 已经 pure enough
* 没有 feature 可以继续 split
* node 里面 instances 太少
* tree depth 达到限制
* Information Gain 太小

Lecture 5 主要强调：

> 不一定要完全 pure，够 pure 就可以 stop。

这和 generalisation 有关。Tree 不是越深越好。太浅会 underfit，太深会 overfit。

---

## 12. Numerical Features 和 Regression Tree

### 12.1 Numerical feature 怎么 split

前面的 examples 主要是 nominal features，例如 Outlook = sunny / rainy / overcast。但 Decision Tree 也可以处理 numerical features。

对于 numerical feature，通常要找一个 threshold 来 split：

$$
x \leq t
$$

和：

$$
x > t
$$

例如 education years 可以 split 成：

$$
EduNum \leq 12
$$

$$
EduNum > 12
$$

本质上还是一样：找到一个 split，让两边的 labels 更 pure。

---

### 12.2 Regression Tree

Decision Tree 也可以做 regression。Classification tree 的 leaf 输出 class label；Regression tree 的 leaf 输出 numerical value，通常是该 leaf 中 training instances 的 average target value。

例如预测 income，如果某个 leaf 里面有几个 training examples，它们的 income 是：

$$
40K,\ 50K,\ 60K
$$

那么这个 leaf 的 prediction 可以是：

$$
\hat{y}=\frac{40+50+60}{3}=50K
$$

所以：

> Classification tree 输出 label。
> Regression tree 输出 average numerical value。

---

## 13. Decision Tree 的优点和缺点

### 13.1 优点

Decision Tree 最大优点是 interpretable。每一个 prediction 都可以沿着 path 解释出来：为什么走这个 branch，为什么最后预测这个 label。

它也比较 fast，prediction 很快，因为只需要从 root 走到 leaf。

它还能处理 non-linear decision boundary，因为不同 branches 可以表达不同 rule combinations。

---

### 13.2 缺点

Decision Tree 最大问题是容易 overfit。尤其是 tree 太深、branch 太多、或者 feature 有很多 unique values 时，tree 很容易记住 training data。

ID3 还有一个特别问题：Information Gain 会偏向 many-valued attributes，所以可能选择像 ID 这种无意义但能让 training data 变 pure 的 feature。

对于 continuous features，tree 通过 threshold 切分，可能会损失一些 information。Regression tree 如果直接用 leaf average，也可能比较粗糙。

---

## Lecture 5 总结

Lecture 5 的核心是：

> Decision Tree 用一系列 feature-based rules 来做 prediction。

我需要重点记住：

Zero-R 是不看 feature，只预测 majority class。
One-R 是只用一个最好的 feature。
Decision Tree 是多层 rule-based model。
Root node 是第一个 split feature。
Branch 是 feature value。
Leaf 是 final prediction。
Pure node 表示里面的 instances 都是同一类。
ID3 是 greedy recursive algorithm。
ID3 每一步选择 Information Gain 最大的 feature。
Entropy 衡量 uncertainty。
Conditional Entropy 衡量知道某个 feature 后还剩多少 uncertainty。
Information Gain 衡量 uncertainty reduction。
Information Gain 高的 feature 更适合 split。
ID3 容易偏向 many-valued feature。
Gain Ratio 可以减轻这个问题。
Decision Tree 很 interpretable，但容易 overfit。
Numerical features 可以用 threshold split。
Regression tree 的 leaf 通常输出 average value。

一句话总结：

> Decision Tree 的本质是：不断选择最能减少 uncertainty 的 feature，把 data 分成越来越 pure 的 subsets，最后形成一组可以解释的 decision rules。
