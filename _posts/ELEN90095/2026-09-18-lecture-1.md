# COMP90086 — AI4R via Systems Thinking

> 本讲用 Systems Thinking 建立 AI for Robotics 的统一框架。核心不是把 AI 看成单独的 algorithm，而是分析 policy、physical system、sampling、delay、uncertainty、policy synthesis 与 human designer 如何共同形成一个 closed loop。

## 1. 这门课所说的 AI4R 是什么

Russell and Norvig 用两个维度描述 AI：目标可以是 **humanly** 或 **rationally**，关注对象可以是 thought process 或 behaviour。本课程关注的是 **acting rationally**：设计能够根据环境信息作出合适 decision，并让 robot 实现目标的 autonomous decision-making algorithms。

这里的理论不仅适用于机器人，也适用于一般 engineering systems。因此 lecture 使用两个近似等价的名称：

- **AI for Robotics (AI4R)**：强调应用对象是 robot；
- **AI for Engineering Systems (AI4Sys)**：把相同框架推广到更广泛的 system；
- **Cyber-Physical Systems (CPS)**：强调 digital computation 与 physical process 的闭环结合。

Robotics 涉及 sensing、acting、motion planning、state estimation、trajectory tracking、reinforcement learning 和 online replanning 等不同领域。Systems Thinking 的作用，是把这些组件放进同一个 block diagram 中，明确它们之间的 interfaces 和相互影响。

Lecture 同时强调 theory 与 implementation 的配合：理论帮助理解 algorithm 的性质与 trade-offs；implementation 则要求实际测试 parameters，并解释结果为何与理论一致或不同。理论与实验出现 mismatch 本身不一定是问题，无法解释 mismatch 才是问题。

## 2. Policy 与 cyber-physical closed loop

**Policy** 是一个 rule、function 或 algorithm。它接收当前可用的 observations，并计算 robot 下一步应采取的 action：

$$
a_k=\pi(o_k;\theta),
$$

其中：

- $o_k$：第 $k$ 个 discrete-time step 可用的 observation；
- $a_k$：policy 输出的 action；
- $\theta$：policy parameters。

每当新的 observation 到达，policy 通常就计算新的 action。因此，policy 本质上是一个 **decision-making algorithm**。

```text
observations
     ↓
Policy π(·; θ) ── actions ──→ Robot in its environment
     ↑                              │
     └──────── observations ────────┘
```

这个 loop 存在明确的 **cyber-physical split**：

- **Cyber side**：运行 policy 的 digital computer；
- **Physical side**：robot 及其 environment；
- **Observations**：physical side 向 cyber side 传递 sensing information；
- **Actions**：cyber side 向 physical side发送 commands。

Policy 的 computation 可以在 onboard computer、附近的 laptop，甚至远程 data centre 上运行。位置本身不是关键；关键是它会影响 communication delay、reliability 和 bandwidth，因此应该在 system model 中明确。

🟨 **核心判断：** 如果一个 system 能画成“policy 根据 observations 输出 actions，robot/environment 再产生新 observations”的闭环，那么它就可以用 AI4Sys 的框架分析。

## 3. Continuous physical world 与 discrete cyber world

真实 robot 在 continuous time 中运动，而 computer 中的 policy 通常在 discrete time 中运行。两者通过 **sampling** 和 **zero-order hold (ZOH)** 连接。

### Sampling：physical → cyber

Sensor 从 continuous-time physical signal 中，在离散时刻取得 measurement：

$$
o_k = y(k\Delta T),
$$

其中 $\Delta T$ 是 sampling period，对应 sampling frequency：

$$
f_s=\frac{1}{\Delta T}.
$$

Sampling rate 会决定 policy 能多快看到 system 的变化。不同 sensors 可以有不同频率，例如 camera 可能是 $10\text{ Hz}$，gyroscope 可能是 $400\text{ Hz}$。因此，一个精确的 block diagram 不应把所有 observations 模糊地画成同一条线，而应在必要时分别表示各 sensor 及其 frequency。

### ZOH：cyber → physical

Policy 在时刻 $k$ 只计算一个 discrete action $a_k$。Physical actuator 需要 continuous command，因此 ZOH 在下一个 action 到来前保持 $a_k$ 不变：

$$
u(t)=a_k,
\qquad k\Delta T\le t<(k+1)\Delta T.
$$

🟦 Sampling 是“在若干时刻读取 continuous signal”；ZOH 是“在两个更新时刻之间保持 action constant”。它们共同完成 continuous-time 与 discrete-time 之间的 interface。

设计此类 system 时，还需要理解 continuous-time modelling、high-fidelity simulation，以及如何在 ZOH assumption 下得到 discrete-time equivalent model。

## 4. External reference 与 time delays

Human operator 通常不直接指定每一步 motor command，而是提供较高层的 **external reference**。例如：

| Application | Human instruction / reference |
|---|---|
| Cruise control | Desired speed setpoint |
| Lane keeping | 开启或关闭 lane-keeping 功能 |
| Autonomous navigation | Destination 或 waypoints |

这些 instructions 往往以不规则、较长的时间间隔更新。Policy 在收到新 reference 前，通常将旧 reference 视为保持不变。Reference 表达“想达到什么目标”；reward function 则尝试把这个目标编码为数学上的 performance measure。

AI4Sys loop 中常见的 delay 包括：

| Delay | 来源 | 例子 |
|---|---|---|
| Sample collection delay | Sensor 需要一段时间收集足够信息 | Camera 通常比 gyroscope 慢 |
| Observation communication delay | Measurement 从 sensor/robot 传到 policy | Mobile network、拥挤 Wi-Fi |
| Computation delay | Policy 计算 action 所需时间 | MPC 或 RL inference 通常比简单 PID 更复杂 |
| Action communication delay | Command 从 policy 传回 actuator | Remote computer 控制 robot |

并非所有 delay 都必须加入 model。如果 robot 运动很慢，而 dedicated Wi-Fi 的 delay 相比 system dynamics 极小，就可以合理忽略。但这种忽略必须是明确的 modelling decision，而不是忘记考虑。

🟨 **重要关系：** observation delay、computation delay 和 action delay 会累积。Policy 使用的可能是较旧的 system information，而 action 真正作用到 robot 时，physical state 已经继续变化。

## 5. Randomness、uncertainty 与 robustness

真实 system 总会存在 uncertainty。设计者需要明确哪些 uncertainty 被忽略，哪些被加入 modelling、simulation 和 testing。

### External uncertainties

External uncertainty 来自 policy 无法控制的因素，例如：

- measurement noise；
- wind、temperature、road friction 等 environmental disturbances；
- policy 没有 preview 时，external reference 的未来变化。

### Internal uncertainties

Internal uncertainty 来自 robot/model/policy 内部，例如：

- 真实 robot mass 或 dimensions 与 simulation model 不同；
- battery voltage 随时间变化，而 model 假设它恒定；
- links 并非完全刚性，gearbox 存在 wiggle；
- motor torque curve 的 static nonlinearity；
- training 时为了 exploration 而主动加入 action noise。

相关术语在不同文献中可能略有差异：

| Term | Lecture 中的常见含义 |
|---|---|
| Stochasticity / uncertainty / disturbance | 影响 robot 的随机性或未知变化的总称 |
| Noise | 通常指 high-frequency disturbance |
| Parameter error | model parameter 与真实 robot parameter 的差异 |
| Constant disturbance | 随时间保持不变的 parameter error |
| Time-varying disturbance | 随时间缓慢变化的 disturbance |
| Static nonlinear disturbance | 真实 static mapping 与 model mapping 的差异 |
| Model mismatch | 可概括多种 model 与现实之间的不一致 |

**Robustness** 表示 policy 面对预期范围内的 uncertainty 时，仍能维持良好 performance。Lecture 提出两个同样重要的挑战：

1. 设计在 uncertainty 下依然 robust and performant 的 algorithm；
2. 通过足够广泛的 tests，demonstrate 并 explain 为什么它是 robust and performant。

这意味着只展示一次成功 run 不足以证明 robustness。应让 system 经历不同 parameter errors、noise、disturbances 和 operating conditions，并分析 performance distribution。

## 6. Policy parameters 与 policy synthesis

每一种 policy 都有 parameters。例如：

| Policy | Parameters | Policy 本身 |
|---|---|---|
| PID | Gains $k_p,k_i,k_d$ | 通常 model-free |
| MPC | Model、horizon、cost、initial state、constraints | Model-based |
| Deep RL | Neural-network architecture 与 weights | Model-free |
| Rule-based control | Rule switching thresholds | 通常 model-free |

Lecture 对 **model-based** 的定义是：policy 或 algorithm 至少包含一个对 system explicit model 具有 physical meaning 的 parameter，例如 robot mass、dimensions 或 dynamics model。若所有 parameters 都没有这样的 explicit physical meaning，则称为 **model-free**。

🟨 **必须说明对象：** “model-based / model-free” 可以描述 policy，也可以描述 policy synthesis algorithm，两者不能混为一谈。例如 neural-network RL policy 本身可以是 model-free，但若它在 model-based simulation 中训练，则 policy synthesis 是 simulation-based，并包含 model information。

### Policy synthesis algorithm

**Policy synthesis algorithm** 用于寻找 policy parameters $\theta$ 的具体数值，使整个 closed loop 展现 desirable behaviour：

$$
\text{hyperparameters/data/model assumptions}
\longrightarrow
\text{policy synthesis}
\longrightarrow
\theta
\longrightarrow
\pi(\cdot;\theta).
$$

Policy synthesis 本身通常也有 parameters，称为 **hyperparameters**。Human designer 需要设定 hyperparameters、分析结果并作出 trade-offs。Synthesis 几乎总是结合某种比例的：

- system data；
- modelling assumptions。

Data collection cost 与 modelling-assumption validity 之间存在权衡。即使 synthesis algorithm 被正确运行，也可能产生 highly undesirable policy，因此 designer 仍必须验证 closed-loop behaviour。

### Reward 在哪里

传统 RL diagram 常画成 environment 把 reward 交给 agent，但 lecture 强调：environment 不会“神奇地知道”设计者想要什么。**Reward function 是由 human designer 指定的，并属于 policy synthesis 的 specification/hyperparameters。**

```text
Human designer
    ↓ reward specification + hyperparameters
Policy synthesis algorithm
    ↓ updates policy parameters θ
Policy π(·; θ)
    ↓ actions
Robot in its environment
    ↓ observations/data
Policy synthesis algorithm / Policy
```

## 7. Block diagrams 与常见 policy architectures

Block diagram 是本讲的核心 Systems Thinking tool。一个 block 应明确：

- inputs；
- outputs；
- functionality；
- adjustable parameters。

Connection 负责把一个 block 的 output 送到另一个 block 的 compatible input。Parameter update 通常比 input/output signals 的更新频率低得多。为了让 diagram 更精确，可以分别标出每个 sensor、signal frequency、delay，以及 physical ground-truth signal 与 measured observation 的区别。

### Nested loops

Nested control 把 policy 分成不同层级：outer loop 根据高层目标产生 **internal reference**，inner loop 负责较快的低层 tracking。

```text
desired location
      ↓
outer-loop location controller
      ↓ desired wheel speed
inner-loop motor-speed controller
      ↓ voltage / torque action
robot
```

Outer loop 与 inner loop 可以运行在不同 frequencies。分层后，每个 controller 只处理适合其 timescale 和 abstraction level 的问题。

### Estimator architecture

Observations 不一定直接等于 policy 需要的 state。Estimator 将 noisy 或 incomplete observations 转换为 state estimate：

$$
\hat s_k=\operatorname{Estimator}(o_{0:k}),
\qquad
a_k=\pi(\hat s_k).
$$

即使使用 RL，也仍可加入 estimator。这样的结构提供 useful inductive structure，并可能比完全 end-to-end learning 更 sample-efficient。

### Path planning + trajectory tracking

Path-planning architecture 通常分成：

```text
high-level goal / waypoints
          ↓
path planner ← current location estimate
          ↓ path or trajectory reference
trajectory-tracking policy
          ↓ actions
robot in its environment
```

Path planner 决定“从当前位置应该走哪条路线”；tracking policy 决定“现在具体输出什么 action 才能沿着该路线运动”。Estimator、planner 和 controller 因此可以作为不同 blocks，各自具有 parameters、frequency 和 uncertainty。

## 重点总结

- AI4R 在本课程中主要研究让 robot **act rationally** 的 autonomous decision-making algorithms。
- Policy 根据 observations 计算 actions；policy 与 robot/environment 构成 closed loop。
- Sampling 把 continuous physical signal 转成 discrete observation；ZOH 将 discrete action 保持到下一次更新。
- Delay 和 uncertainty 是 system 的一部分，必须明确决定 modelling、simulation 和 testing 中包含哪些因素。
- Policy parameters 由 policy synthesis algorithm 决定；synthesis 的 hyperparameters 和 reward specification 由 human designer 选择。
- Model-based/model-free 必须说明是在描述 policy 还是 synthesis algorithm。
- Nested loops、estimator、path planning 都是在基本 closed-loop diagram 内进一步展开的 policy architectures。
