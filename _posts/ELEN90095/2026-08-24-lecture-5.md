# AI for Robotics — Model Predictive Control (MPC) Framework

> **课程主题：** 从无限时域的 Markov Decision Process（MDP）出发，理解如何通过一系列近似得到有限时域的 Model Predictive Control（MPC），以及 MPC 如何以 Receding Horizon Control（RHC）的方式在线运行。

## 1. MPC 的核心直觉

Model Predictive Control（MPC，模型预测控制）是一种**策略（policy）**：在每一个离散时间步，它都会求解一个基于模型的优化问题，规划当前与未来多个时间步的动作；但系统实际只执行规划序列中的第一个动作，然后根据新观测重新规划。

因此，MPC 同时包含三个关键词：

- **Model：** 用离散时间模型预测系统如何响应候选动作。
- **Predictive：** 不只考虑当前动作，还向前观察一个有限的预测时域（prediction horizon）。
- **Control：** 把第一步最优动作施加到真实系统，并通过反馈不断修正计划。

以车辆车道保持为例，一次控制循环包括：

1. 根据摄像头等观测估计当前状态，例如横向位置、车速及前方道路形状。
2. 用车辆动力学模型预测不同转向序列造成的未来轨迹。
3. 根据设计者定义的目标函数选择“最好”的动作序列，例如惩罚车辆偏离车道中心的程度。
4. 只执行该序列中的第一个转向动作。
5. 在下一个时间步取得新观测，更新状态估计并再次求解。

MPC 解决的是一个 **multi-stage decision-making problem**。它不是一次性算出一条永远不变的轨迹，而是在闭环中持续“预测—优化—执行—反馈”。

## 2. 优化问题的基本结构

一个优化问题由三部分构成：

| 部分 | 含义 | 典型记号 |
|---|---|---|
| 决策变量（decision variables） | 优化器可以调整的量 | $x\in\mathbb{R}^{n_x}$ |
| 目标函数（objective function） | 衡量一个决策有多好，输出标量 | $f(x)$ |
| 约束（constraints） | 决策必须满足的条件 | $x\in\mathcal X$ |

一般的最大化形式为：

$$
x^*=\arg\max_{x\in\mathbb{R}^{n_x}} f(x)
\quad\text{s.t.}\quad x\in\mathcal X.
$$

其中：

- $f^*$ 是最优目标值，是一个标量；
- $x^*$ 是取得最优值的决策变量；
- `argmax` 返回“哪个决策最好”，而 `max` 返回“最好能达到多少”。

最大化 reward 与最小化 loss 本质等价：

$$
\max_x f(x)=-\min_x[-f(x)].
$$

### 2.1 参数化优化（parametric optimization）

相对于一次优化求解，所有**不是决策变量**的量都视为参数。若参数集合记作 $\theta$，则：

$$
x^*(\theta)=\arg\max_x f(x;\theta)
\quad\text{s.t.}\quad x\in\mathcal X(\theta).
$$

在 MPC 中，当前状态估计会随真实时间更新，所以它是每次调用优化器时的新参数。预测时域 $N$、动力学矩阵、代价权重和边界也是参数；预测区间中的状态与动作则是决策变量。

## 3. 把 MDP 写成优化问题

给定状态空间 $\mathcal S$、动作空间 $\mathcal A$、reward $r(s_k,a_k)$、折扣因子 $\gamma\in[0,1)$ 与策略集合 $\Pi$，无限时域 MDP 希望寻找最优策略：

$$
\pi^*=\arg\max_{\pi\in\Pi}
\mathbb E_{\pi}\left[
\sum_{k=0}^{\infty}\gamma^k r(s_k,a_k)
\,\middle|\,
s_0=s,\ a_0=a
\right].
$$

把策略与动力学显式写成约束，可表示为：

$$
\begin{aligned}
\pi^*=\arg\max_{\pi\in\Pi}\quad
&\mathbb E_{\pi}\left[\sum_{k=0}^{\infty}\gamma^k r(s_k,a_k)\right]\\
\text{s.t.}\quad
&a_k=\pi(s_k),\\
&s_{k+1}=f_d(s_k,a_k,\text{noise}),\\
&s_k\in\mathcal S,\quad a_k\in\mathcal A,
\qquad k=0,1,\ldots
\end{aligned}
$$

### 3.1 为什么一般 MDP 很难直接求解

| “Curse” | 困难来源 | MPC 的典型处理方式 |
|---|---|---|
| 无限数量的约束 | 时域一直延伸到无穷 | 截断为有限预测时域 |
| 在无限参数化策略空间中搜索 | 决策变量是整个函数 $\pi$ | 每个时间步直接优化有限动作序列 |
| 存储完整策略 | 连续状态空间中的策略可能是无限维对象 | 由在线优化器隐式定义策略 |
| 多维期望难以计算 | 随机动力学与一般 reward 共同造成复杂积分 | nominal MPC 中去掉 noise 与 expectation |
| 非线性、非凸约束 | 一般模型难以稳定快速求解 | 常用线性模型、线性约束与二次目标 |

这些处理不是免费的：它们用可计算性换取近似解，因此 MPC 一般不保证等于原 MDP 的全局最优策略。

## 4. 从无限时域 MDP 到有限时域 MPC

### 4.1 分割无限时域回报

在预测时域长度 $N$ 处分割无限和：

$$
\sum_{k=0}^{\infty}\gamma^k r(s_k,a_k)
=
\sum_{k=0}^{N-1}\gamma^k r(s_k,a_k)
+
\sum_{k=N}^{\infty}\gamma^k r(s_k,a_k).
$$

利用 Q-function 的定义，尾部可写成：

$$
\sum_{k=0}^{N-1}\gamma^k r(s_k,a_k)
+\gamma^N Q^{\pi}(s_N,a_N).
$$

$\gamma^N$ 的作用是把从时间 $N$ 开始定义的 Q-function 放回原始时间索引。随后，用可计算的近似值 $\hat Q^{\pi}$ 代替真实尾部：

$$
Q^{\pi}(s_N,a_N)\approx \hat Q^{\pi}(s_N,a_N).
$$

这是从精确 MDP 到实际 MPC 的关键近似：优化器只显式观察前 $N$ 个阶段，而 $N$ 之后的长期后果由 terminal reward / terminal cost 近似概括。

### 4.2 从优化策略改为优化动作序列

MPC 不再一次性搜索整个策略函数 $\pi$，而是在每个真实时间步优化有限的动作序列。去掉 noise 与 expectation 后，deterministic MPC 可写为：

$$
\begin{aligned}
\arg\max_{a_0,\ldots,a_N}\quad
&\sum_{k=0}^{N-1}\gamma^k r(s_k,a_k)
+\gamma^N\hat Q^{\pi}(s_N,a_N)\\
\text{s.t.}\quad
&s_0=\hat s_{\text{current}},\\
&s_{k+1}=f_d(s_k,a_k), && k=0,\ldots,N-1,\\
&a_k\in\mathcal A, && k=0,\ldots,N,\\
&s_k\in\mathcal S, && k=0,\ldots,N.
\end{aligned}
$$

这看起来只是 MDP 的有限时域近似，但还有一个重要变化：优化程序本身成为了策略。给定当前状态，它返回动作；状态一变，就重新求解。

### 4.3 预测时域与尾部近似的权衡

| 预测时域 | $\hat Q$ 质量 | 典型结果 |
|---|---|---|
| 短 | 高 | 计算快，而且好的尾部近似提供了长期信息；可能达到很好的闭环表现 |
| 短 | 低 | 最危险的组合；控制器过度依赖错误的 terminal approximation |
| 长 | 高 | 通常表现稳健，但可能增加了不必要的计算量 |
| 长 | 低 | 更长的显式 look-ahead 能削弱尾部误差的影响，但计算成本和模型误差暴露增加 |

若尾部恰好是真实的 $Q^*$ 或 $V^*$，理论上很短的 horizon 也足够；当 $\hat Q$ 不准确时，增大 $N$ 可降低对它的依赖。在折扣问题中，尾部误差进入目标函数时受到 $\gamma^N$ 缩放。

但 horizon 并非越长越好：更长的时域意味着更多状态与动作决策变量、更高在线计算成本，以及更长距离上的模型误差累积。工程上的常见原则是：**在每个 sampling interval 的实时期限内，使用能够可靠求解的最长合理 horizon。**

## 5. MPC Policy：Receding Horizon Control

在真实时间步 $j$，MPC 的事件顺序为：

1. **Measurement：** 获取当前观测 $o_j$。
2. **Estimation：** 从观测得到当前状态估计 $\hat s_j$。
3. **Optimization：** 以 $\hat s_j$ 为初始状态，求解未来动作序列。
4. **Control：** 只对真实系统施加第一项 $a_j^*$。
5. 系统演化到下一时刻，取得 $o_{j+1}$，并重复上述过程。

若本次优化得到：

$$
(a_j^*,a_{j+1}^*,\ldots,a_{j+N}^*),
$$

实际只执行 $a_j^*$。下一时刻会用新状态重新计算后续动作，因此先前的 $a_{j+1}^*$ 只是旧信息下的计划，并不会被盲目执行。

### 5.1 两套时间索引

理解 receding horizon 时要区分：

- **真实时间（real-world time）$j$：** 系统实际向前演化的时间步。
- **预测时间（prediction-horizon time）$k$：** 每次优化内部从 $0$ 到 $N$ 的虚拟时间步。

每当真实时间从 $j$ 前进到 $j+1$，预测窗口也向前滚动一次，并再次从预测索引 $k=0$ 开始。这就是“receding horizon”的含义。

### 5.2 闭环价值

重复优化带来反馈：

- 新观测可以修正模型误差与外部扰动造成的偏差；
- 状态估计器可以融合不完整或带噪声的 observations；
- 每次只承诺一个动作，避免长期依赖已经过时的预测。

同时，求解器必须在一个 sampling interval 内完成计算，否则控制动作会错过实时截止时间。

## 6. Linear-Quadratic MPC 与 OSQP

课程聚焦于容易在线求解的一类 MPC：

- quadratic objective function；
- linear dynamics 与 linear constraints；
- 状态和动作采用 box constraints。

典型的 time-invariant linear-quadratic MPC 为：

$$
\begin{aligned}
\min_{a_0,\ldots,a_{N-1}}\quad
&\sum_{k=0}^{N-1}\gamma^k
\left(s_k^\top Qs_k+a_k^\top Ra_k\right)
+\gamma^N s_N^\top Ps_N\\
\text{s.t.}\quad
&s_0=\hat s_{\text{current}},\\
&s_{k+1}=As_k+Ba_k, && k=0,\ldots,N-1,\\
&l_a\le a_k\le u_a, && k=0,\ldots,N-1,\\
&l_s\le s_k\le u_s, && k=0,\ldots,N.
\end{aligned}
$$

各参数的作用如下：

| 参数 | 作用 |
|---|---|
| $N$ | prediction horizon 长度 |
| $Q$ | 每一步 state cost 的二次权重 |
| $R$ | 每一步 action cost 的二次权重 |
| $P$ | terminal state cost 的二次权重 |
| $A$ | 线性动力学中的状态演化矩阵 |
| $B$ | 动作对下一状态的影响矩阵 |
| $l_s,u_s$ | 状态上下界 |
| $l_a,u_a$ | 动作上下界 |

若目标是追踪参考状态和参考动作，应惩罚相对参考值的偏差，例如：

$$
(s_k-s_{\mathrm{ref},k})^\top Q(s_k-s_{\mathrm{ref},k})
+
(a_k-a_{\mathrm{ref},k})^\top R(a_k-a_{\mathrm{ref},k}).
$$

### 6.1 OSQP 的标准形式

OSQP 求解的 quadratic program（QP）形式为：

$$
\begin{aligned}
\min_{x\in\mathbb R^{n_x}}\quad
&\frac{1}{2}x^\top P_{\mathrm{OSQP}}x+q^\top x\\
\text{s.t.}\quad
&l\le A_{\mathrm{OSQP}}x\le u.
\end{aligned}
$$

因此，需要把 MPC 的所有预测状态和动作堆叠成一个大决策向量 $x$，再把动力学与 box constraints 编码进线性约束。这里存在常见的符号冲突：MPC 的 terminal-cost matrix $P$ 与 OSQP 的 quadratic matrix $P_{\mathrm{OSQP}}$ 不是同一个对象；MPC dynamics matrix $A$ 与 OSQP constraint matrix $A_{\mathrm{OSQP}}$ 也不是同一个对象。

### 6.2 Hard constraints 与 soft constraints

Hard constraint 必须严格满足；一旦约束集合为空，优化问题就 infeasible。Soft constraint 则引入额外的 slack variable，允许有限违反约束，同时在目标函数中高额惩罚违反量。概念上可写成：

$$
g(s_k,a_k)\le \lambda_k,
\qquad \lambda_k\ge 0,
$$

并在 cost 中加入：

$$
\rho_1\lambda_k+\rho_2\lambda_k^2,
$$

其中较大的 $\rho_1,\rho_2$ 让控制器只在避免 infeasibility 所必需时违反约束。安全关键的物理限制通常仍应保留为 hard constraints。

## 7. 建模、估计与设计选择

实际 MPC 不只是在“选一个求解器”，还要处理模型与信息的不完美：

| 实际问题 | 常用处理 |
|---|---|
| dynamics 非线性 | 在当前 operating point 附近 linearize；或使用 iterative / RTI-MPC |
| reward 非二次 | 进行 quadratic Taylor approximation |
| 模型参数未知 | 通过实验进行 system identification |
| observation 不包含完整状态 | 使用 state estimator，例如 Kalman filter |

主要设计权衡包括：

- 是否使用 discount factor；
- prediction horizon 长短；
- 模型 fidelity 与计算复杂度；
- 约束的数量、耦合程度与形式；
- state cost 与 action cost 的相对权重；
- linear、quadratic 或其他 reward/cost；
- terminal reward/cost 采用零、单步目标、Lyapunov/Riccati 解，还是 learned value approximation。

在更广的谱系中，LQR 是线性、二次、无约束 deterministic control 的经典形式；nominal MPC 加入有限时域与约束；LQG 处理线性二次 Gaussian 随机系统；RTI-MPC 面向 nonlinear dynamics 的实时迭代；MDP 与 RL 则从随机最优控制的另一条路径处理策略与长期价值。

---

## 8. 核心总结

1. MPC 是一个在线 policy：每个离散时间步都求解一次有限时域优化问题。
2. 它用模型预测候选动作的未来结果，以 reward/cost 排序，并显式满足状态与动作约束。
3. 从 MDP 到 MPC 的关键变化是：无限时域改为有限时域、真实尾部价值改为 $\hat Q$、策略搜索改为有限动作序列优化，并常把随机非线性问题近似为确定性线性二次问题。
4. MPC 每次只执行第一项动作，然后根据新观测重新规划，因此又称 Receding Horizon Control。
5. horizon 越短，越依赖 terminal approximation；horizon 越长，计算量与模型误差暴露越大。
6. Linear-quadratic MPC 可整理为 QP，并交给 OSQP 等求解器；实时系统必须在 sampling interval 内完成求解。
7. 一个可用的 MPC 系统还需要合理的模型、state estimator、约束设计、cost 权重与 infeasibility 处理机制。
